# 동 단위 예측 모델 설계 계획

이 문서는 모델 재설계의 계획 원문이다. 진행 상태는 `docs/model-build-process.md`에서 관리한다.

## 0. 배경과 목표

현재 채택 모델(M0+R0, γ=0)은 246개 동에 **동일한 +13.6%**를 내려보낸다. 동별 차이가 전혀 없으므로 "동 단위 예측 서비스"가 아직 성립하지 않았고, 예측구간 coverage도 65.5%로 목표에 미달한다.

따라서 이번 설계의 목표는 "더 좋은 모델 하나"를 만드는 것이 아니다.

> **δ(동별 상대 변화)에서 기준선을 유의하게 이기는 모델을 찾고, 못 찾으면 nowcast 중심으로 제품을 전환하는 판정 체계**를 만든다.

δ가 기준선을 못 이기는 결과도 실패가 아니라 제품 방향 결정이다. 그 경우에도 nowcast와 신뢰도 표시, 구조 정보만으로 "실거래 공개 시차 해소"라는 검증 가능한 가치가 남는다.

## 1. 설계 전제: 문제를 3개의 독립 모델링 문제로 분해

`y = μ + δ` 분해를 그대로 아키텍처로 가져간다.

| 문제 | 예측 대상 | 모델 복잡도 | 검증 주기 |
|---|---|---|---|
| **P1. Nowcast** | 잠정 분기(현재)의 확정 지수 | 낮~중 | 수개월 |
| **P2. δ 예측** | 동 i의 서울 대비 12개월 상대 변화 | 중~높 | 12개월+ |
| **P3. μ 참고치** | 서울 공통 12개월 변화 | **모델링 안 함** (기준선) | — |

μ를 모델링하지 않는 이유는 독립 관측이 연 단위로 20개 남짓(2006~2026)이어서 어떤 복잡한 모델도 통계적으로 정당화할 수 없기 때문이다. 현재 +13.6%가 전부 μ에서 나오는 구조 자체가 문제였다. 복잡도 예산은 전부 δ에 쓴다.

### 선행 조건 — μ 가중 방식 확정

δ의 정의가 μ 가중 방식에 달려 있으므로 **거래가중/단순평균/재고가중 중 하나를 먼저 확정**한다.

**재고(세대수)가중을 권한다.** `complex.total_households`가 이미 있고, 거래 구성 변화에 흔들리지 않으며, "서울 아파트 전체 대비"라는 UI 해석과 일치한다.

단 매매가 없던 단지는 `complex`에서 동 매핑이 안 되는 문제(`docs/data-and-schema.md` §2.3)가 있다. **세대수 합산의 동 매핑 커버리지를 먼저 측정하고, 결과를 보고 결정해 결정 기록에 남긴다.**

## 2. 모델 후보군 설계

### 2.1 Track 0 — 지수 추정 개선 (모든 것의 토대)

δ 모델을 만들기 전에 지수 자체를 고쳐야 한다.

**이유 — 가짜 평균회귀.** 거래가 적은 동일수록 측정오차 `e`가 크다. feature(과거 변화)와 target(미래 변화)이 같은 `e`를 반대 부호로 공유하므로, **모델이 실재하지 않는 역추세를 학습한 뒤 백테스트에서 실력처럼 보인다.** 이걸 안 고치면 Track C의 모든 비교가 오염된다.

| 후보 | 방식 | 산출물 |
|---|---|---|
| **0-A** 사후 shrinkage | 기존 hedonic 동×분기 시점효과를 `n_sales` 기반으로 구 평균 쪽으로 수축 (Empirical Bayes) | 구현 비용 최소, 기존 파이프라인 구조 유지 |
| **0-B** Multilevel hedonic | 시점효과에 서울→구→동 random effect를 넣은 mixed model로 재추정 | SE가 모델에서 자연스럽게 나옴 |
| **0-C** 인접 동 가중 pooling | 행정 계층 대신 경계 인접성(`dong_boundary`로 인접 행렬 산출) 기반 수축 | 한강·생활권 동조화 반영, 0-A/0-B와 비교용 |

**어느 쪽이든 `dong_index`에 `log_index_se` 컬럼 추가는 필수다.** 현재 스키마에 지수 표준오차 자리가 없는데, 이게 없으면 gate 개선(§5), measurement-error 구간 조정(§2.4), 측정오차 진단(§4.4)이 전부 불가능하다.

**순서: 0-A부터 시작해 0-B와 지수 안정성(분기 간 수정폭, 저거래 동 분산)을 비교한다.**

### 2.2 Track N — Nowcast (새 헤드라인)

잠정 분기의 지수는 신고 미완료분 때문에 편향된다.

| 후보 | 방식 | 필요 데이터 | 한계 |
|---|---|---|---|
| **N-1** 도착률 보정 | 과거 snapshot에서 "분기 종료 후 d일 시점 관측 건수/최종 건수" 도착 곡선을 추정해 잠정 지수를 재가중 | **snapshot 이력** — 지금부터 적재 시작해야 함 | 초기 수분기는 곡선 추정 불가 |
| **N-2** 상태공간(Kalman) | 참 지수를 잠재 상태로, 잠정 관측을 노이즈 관측으로 두고 필터링 | `dong_index` + SE | 동별 적용 시 소표본 문제 → 구 단위 공통 성분과 결합 |
| **N-3** 수정폭 회귀 | (확정치 − 잠정치)를 잠정 시점 관측 특성(경과일수, 관측 건수, 취소율)으로 회귀 | 계약일 기반 근사 vintage | 조기·지연 신고 근사 오차 |

**현실적 경로:** snapshot이 없으므로 **N-3을 계약일+30일 근사 규칙으로 먼저 구축**하고, 오늘부터 원천 snapshot 적재를 시작해 이후 구간은 실제 vintage로 N-1을 학습·검증한다.

Nowcast는 수개월 내 검증되므로 제품 신뢰 형성의 엔진이 된다.

### 2.3 Track C — δ 모델 (제품 성립 조건이 걸린 트랙)

복잡도 오름차순으로 사다리를 놓고, **각 단은 아래 단을 유의하게 이겨야 올라간다.**

| 후보 | 방식 | feature | 예상 강점·약점 |
|---|---|---|---|
| **C-0** δ̂=0 | 기준선 (현재 R0) | — | 이길 대상 |
| **C-1** 구 평균 | 구 단위 상대 모멘텀을 동에 배정 | 구 지수 | 두 번째 기준선 |
| **C-2** 수축 모멘텀 | 동별 과거 4분기 상대 변화 × 수축계수 λ(SE 함수) | `log_index` 이력 + SE | 가짜 평균회귀를 정면 처리한 최소 모델. **가장 먼저 진지하게 볼 후보** |
| **C-3** 정규화 선형 (elastic net) | pooled 횡단면-시계열 회귀 | 유지 feature 전부 | 해석 가능, 계수 부호 점검 용이 |
| **C-4** LightGBM pooled | 전체 동 pooled, `1/se²` 표본 가중, monotonic 제약 검토 | 위 + 상호작용 | 비선형 포착 vs 소표본 과적합 |
| **C-5** 계층 베이지안 | 서울→구→동(또는 인접 기반) random slope | 소수 핵심 feature | 예측분포가 나와 §2.4 구간과 자연 결합, 비용 높음 → C-2·C-3이 신호를 보일 때만 |

C-4에서 **구·동 식별자 인코딩은 partial pooling이 아니다.** 지역 정보는 Track 0에서 처리된 지수로 흡수한다.

**feature 구성 주의점:**

1. **feature 기점과 target 기점 분리** — feature를 `t−1` 분기 지수까지로 끊어 target과 같은 분기 추정치를 공유하지 않게 한다. 이렇게 했을 때 성능이 크게 빠지면 기존 신호가 측정오차였다는 증거다.
2. **전세 feature break** — `jeonse_*`는 2021-06 전월세신고제 전후 커버리지가 다르다. 현재 `dong_feature`에 break 표시가 없으므로 break 더미를 넣거나 2021H2 이후 origin에서만 쓰는 정책을 명시한다. 기존 선별에서 전세 묶음 기여가 가장 컸으므로, **그 기여가 break 전후 어느 구간에서 나왔는지 재확인이 필요하다.**
3. **추가할 feature (데이터 확보 후)** — 정책 문턱 대비 거래가 분포(`share_above_threshold`, `median_to_threshold`; `trade_sale`에서 바로 산출, 문턱 이력만 `policy_events`로 관리), 거리 가중 인근 준공 물량(`dong_boundary` centroid + `completed_hh`).
   교통 호재·입주 예정·주담대 금리는 데이터가 없으므로 **v1 feature 목록에 넣지 않는다.** ECOS API 키 확보(주담대 금리)가 그중 가장 싼 항목이다.

### 2.4 Track I — 예측구간

| 후보 | 방식 | 조건 |
|---|---|---|
| **I-1** split conformal + measurement-error 조정 | rolling 잔차 분위수 + 지수 SE가 큰 동의 구간 가산 확대 | SE 저장 선행. MVP 권장 |
| **I-2** adaptive conformal | 최근 origin 잔차로 폭 갱신 | label 12개월 지연 → 3·6개월 horizon 잔차를 선행 신호로 사용 검토 |
| **I-3** 계층모형 예측분포 | C-5 채택 시 | C-5 선행 |

구간의 대상은 **추정지수 기준**으로 고정하고(검증 가능성), nominal coverage를 **80%로 먼저 선언**한 뒤 평가한다. 기존 65.5%는 nominal 80% 기준이면 명백한 undercoverage이므로 구간 재설계 대상이다. "실측값 공개(결정 37)" 원칙은 유지하되 재설계 후 수치로 갱신한다. **δ와 μ 각각에 구간을 낸다.**

## 3. 사용자에게 보여줄 데이터

표시 원칙을 현재 스키마에 매핑한 결과다.

### ① 헤드라인 — 현재 상태 추정 (nowcast)

- 최근 4분기 변화율 + 구간, 잠정·확정 상태 배지
- 출처: `dong_index` + 신설 `dong_nowcast`. 또는 `dong_prediction`에 `horizon_q=0` 행으로 넣는 방안도 가능하나, `status` CHECK가 `PREDICTED`/`INSUFFICIENT_SALES`뿐이라 스키마 변경이 필요하다

### ② 서울 대비 12개월 상대 위치 (δ) — 성립 조건 통과 시에만

- "서울 평균보다 강할 확률 X%" (예측분포에서 P(δ>0))
- 상대 변화 추정 ±구간. **구간이 0을 포함하면 "서울 평균과 구분되지 않음" 문구를 강제한다**
- 출처: `dong_prediction`에 `relative_hat`, `lower`/`upper`는 있으나 **확률 컬럼(`prob_above_seoul`)과 δ 전용 구간 컬럼이 없어** 스키마 확장이 필요하다
- 미통과 시: 비공개 또는 "실험적" 라벨

### ③ 데이터 신뢰도 블록 (모든 화면 필수)

- 최근 4분기 거래 건수(`dong_feature.sale_n_all_4q`), 거래 단지 수, 상위 1개 단지 거래비중, 지수 추정오차 등급(SE 3구간)
- 거래 단지 수·집중도는 현재 DB에 없다 → `trade_sale`에서 집계해 `dong_feature`에 `n_complexes_4q`, `dominant_complex_share_4q` 추가 (gate 입력이기도 하다)

### ④ 시장 구조 정보 (사실, 추정과 시각 분리)

- 전세가율·전세 비중(`jeonse_ratio_4q`, `jeonse_share_4q`), 정비사업 단계별 구역 수(`rz_*`), 준공 이력(`completed_hh_*`), 최근 매매 목록·면적대 분포(`trade_sale`), 단지 정보(`complex`)
- 정비사업엔 "2026-06 시점 자료, 해제·완료 구역 미반영" 각주 (생존 편향 고지)

### ⑤ 참고 접힘 — 12개월 절대 변화율

- μ는 "모델 예측이 아닌 기준선 참고치" 문구, 2025Q4 이후 제도 환경 외삽 고지

### ⑥ 지도

- 색상은 점추정 연속값이 아니라 **P(δ>0) 또는 구간 범주** 기준
- "오를 동 TOP N" 정렬 금지. 정렬 제공 시 구간 폭 병기
- gate 미통과 동은 회색 + `insufficient_evidence` 사유 표시(거래 부족·단지 집중·구간 과대 중 무엇인지)

### ⑦ 투명성 페이지

- origin별 백테스트 성능, 약했던 국면, 제공률, coverage 실측치 공개 — 신뢰 자산으로 쓴다

## 4. 성능평가 설계

### 4.1 검증 프로토콜

- **Rolling-origin, embargo 필수.** origin T의 학습 표본은 `s + 4 ≤ T`(target 확정 규칙 반영 시 더 앞당긴다). 평가 코드가 `s ≤ T`로 되어 있으면 미성숙 target 누수다 — **코드로 가장 먼저 확인할 항목이며, 기존 성능 수치의 유효성이 여기 걸려 있다.**
- feature는 as-of 원칙: 계약일+30일 규칙, 해제사유발생일 필터, 정비사업 인가일 이후 반영, 금리는 origin 직전 공개분만
- origin 범위: 2015Q1~2025Q3 분기별 (target 성숙분까지만 정식 평가). **2025Q4 이후 origin은 별도 "current regime monitoring"으로 분리** — nowcast·3/6개월 결과만 우선 보고하고 12개월은 성숙 후 본다

### 4.2 지표 체계 (δ 중심)

| 지표 | 판정 용도 |
|---|---|
| δ MAE — C-0(δ̂=0) 대비 개선폭 + 신뢰구간 | **성립 조건 1** |
| δ MAE — C-1(구 평균) 대비 개선폭 + 신뢰구간 | **성립 조건 2** (동 세분화의 추가 가치) |
| origin별 Spearman 순위상관의 **분포** (평균 금지) | 지도·정렬 기능의 유효성 |
| 절대 변화율 MAE, 방향 일치율 | 보조 |
| nowcast: 잠정→확정 수정폭 MAE, 무보정 대비 개선 | Track N 판정 |

### 4.3 유의성 — 명목 표본수를 믿지 않는다

동×origin 표본은 (i) 4분기 horizon 중첩으로 인접 origin 오차가 3분기씩 겹치고, (ii) 같은 origin 내 모든 동이 μ 오차를 공유하므로 실제 정보량이 훨씬 적다.

- **origin 연도 단위 block bootstrap**으로 모든 지표에 신뢰구간
- 모델 쌍 비교는 **중첩 horizon 보정(HAC) Diebold–Mariano 검정**
- 채택 규칙을 사전 고정: "개선폭 신뢰구간이 0을 제외하고 DM p<0.05일 때만 상위 후보 채택". **점추정 차이만으로 사다리를 오르지 않는다.**

### 4.4 측정오차 진단 배터리 (백테스트 결과 승인 전 통과 필수)

1. feature 기점을 `t−1`로 옮겼을 때 성능 하락폭 측정 — 급락하면 신호가 `e`였다는 뜻
2. 지수 SE 구간별로 모멘텀·역추세 계수(또는 SHAP)가 달라지는지 — 저거래 동에서만 강한 역추세면 가짜
3. 거래량 상위(저SE) 동 부분집합 성능 별도 보고 — 전체 대비 격차 자체가 점검 신호

### 4.5 국면별 층화 보고

상승·하락·전환기, 금리 상승·하락기, 규제 발표 직후, 거래 급감기로 층화해 보고한다. `market_event` 테이블을 층화 기준일로 재활용하되, **분류 규칙은 평가 전에 고정**하고 사후 라벨은 보고에만 쓴다(feature·서빙에 쓰면 누수).

### 4.6 Gate 적용 백테스트

각 origin에서 당시 정보로 gate를 적용하고 **통과 동에서만 성능을 산출**한다. origin별 제공률과 미제공 동 특성(자치구·가격대·거래량)을 함께 보고한다.

gate 임계값(τ_ci, n_min, τ_dom)은 (δ 성능, coverage, 제공률) 3차원 trade-off 곡선을 그려 결정하고 결정 기록에 남긴다. 현행 "4분기 20건" 단일 기준을 SE·단지 집중도 복합 기준으로 대체하는 근거가 여기서 나온다.

### 4.7 Coverage 평가

nominal 80% 선언 → empirical coverage를 전체·국면별·표본수별·SE별·gate 상태별로 분해 기록한다. **평균 구간 폭도 함께 본다** — coverage를 맞춰도 폭이 거래비용(±수%)을 넘으면 정보 가치가 없다는 판정이 가능해야 한다.

## 5. 실행 순서와 의사결정 게이트

```
Phase 0 (즉시): embargo 코드 검증 · 기존 "벤치마크가 모델보다 낫다" 관찰 재확인
              · snapshot 적재 시작 · dong_index에 SE 컬럼
Phase 1: Track 0 (지수 shrinkage + SE) → 지수 안정성 비교
Phase 2: Track N (N-3 근사 nowcast) → 수정폭 개선 확인 → 헤드라인 ① 확보
Phase 3: Track C 사다리 (C-2 → C-3 → C-4) — 4.4 진단 배터리 통과 + DM 검정
   ├─ 통과: 헤드라인 = nowcast + δ, dong_prediction 스키마 확장 후 적재
   └─ 실패: 헤드라인 = nowcast + 구조 정보, δ는 비공개·실험 표시
Phase 4: Track I 구간 재설계 → coverage 재평가 → gate 임계값 확정
Phase 5 (지속): current regime monitoring, 한국부동산원 지수 정기 대사
```

핵심은 **Phase 3의 분기**다. δ가 기준선을 못 이기는 결과도 제품 방향 결정이며, 그 경우에도 nowcast와 신뢰도 표시, 구조 정보로 검증 가능한 가치가 남는다.
