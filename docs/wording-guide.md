# 화면 문구 가이드

> 작성 2026-09-17. `investment-support-plan.md` §5의 규칙을 문장 단위로 내린 문서다. payload는 코드값만 보내고(`payload-schema.md` §6), 코드값을 문장으로 바꾸는 사전이 여기 있다. 산출 스크립트가 만드는 문자열(`structure_desc`, `peers[].reason`)의 사전도 여기 있다.
> `front/scripts/check-wording.mjs`의 금지 목록은 §2를 그대로 옮긴다.

## 1. 원칙

1. 관측을 말한다. 원인, 전망, 우열을 말하지 않는다.
2. 숫자에는 오차나 표본 상태가 붙는다. 붙일 수 없는 숫자는 내지 않는다.
3. 사용자에게 무엇을 하라고 하지 않는다. "확인해 보세요"까지는 허용, "고려해 보세요"부터 금지.
4. 문장은 "~해요"체. 화면 한 줄에 들어가게 40자 안쪽.
5. 금지어는 부분 문자열로 검사한다. 합성어에 들어가도 걸린다. 걸리면 단어를 바꾼다.

화면 전체의 말투는 쉽고 자연스러운 대화체로 통일한다. 전문용어와 행정적인 표현을 줄이고, 오류 문구에는 사용자가 이어서 할 수 있는 행동을 함께 적는다. 지나치게 장난스럽지 않은 친근한 존댓말을 쓴다.

| 상황 | 쓰지 않는 문장 | 쓰는 문장 |
|---|---|---|
| 완료 | 회원가입이 정상적으로 완료되었습니다 | 가입이 완료됐어요 |
| 조회 오류 | 해당 데이터를 조회할 수 없습니다 | 데이터를 불러오지 못했어요. 다시 시도해주세요 |
| 인증 | 로그인이 필요합니다 | 계속하려면 로그인해주세요 |
| 버튼 | 확인을 진행합니다 | 확인하기 |

## 3. 코드값 → 문장

### 3.0 지역 선택

첫 화면의 법정동 목록에는 별도의 자치구 선택 제목을 두지 않는다. 지도에만 자치구 이름을 표시하고,
자치구를 선택하면 해당 지역으로 확대해 법정동을 표시한다. 선택 뒤 이전 단계로 돌아가는 버튼은
`서울 전체`로 쓴다. 법정동 목록에서 동을 선택할 때는 자치구와 검색·필터 조건을 그대로 두고
해당 동의 상세만 연다.

검색 패널의 제목은 `어느 동을 살펴볼까요?`로 쓰고, `법정동 검색`, `자치구 선택`, `조건 필터`를
시각적으로 분리한다. 검색창에는 검색 아이콘과 `예: 개포동, 강남구`를 표시한다. 자치구의 전체
선택지는 `서울 전체`로 쓰며, 조건 필터가 접혀 있어도 적용 개수를 항상 표시한다.

조건 필터를 펼치면 `표본 상태`, `㎡당 매매 중앙가`, `클러스터`, `지역 태그 정렬`을 각각
접고 펼칠 수 있는 묶음으로 표시한다. 필터 패널은 동 목록 위에 떠서 목록 높이를 줄이지 않는다.
한 번에 한 묶음만 펼치며, 화면이 낮을 때는 조건 필터 안에서 스크롤한다. 패널 바깥을 클릭하거나
키보드 포커스가 벗어나거나 `Esc`를 누르면 자동으로 닫는다. 각 묶음에는 `전체` 또는
`{n}개 선택`을 표시한다.

지역 태그는 한 번에 하나만 선택하며, 태그에 해당하는 동만 남긴 뒤 원래 관측값의 내림차순으로
정렬한다. 필터 버튼은 `정비사업 구역 많은 순`, `거래 많은 순`, `전세가율 높은 순`,
`최근 준공 많은 순`, `노후 단지 많은 순`으로 쓴다.

### 3.1 표본 주의 flag (`sample_flags`)

| 코드 | 문장 | 위치 |
|---|---|---|
| `FEW_SALES` | 최근 1년 매매가 적어 변화율 오차가 커요 | 표본 상태 블록 맨 위 |
| `ONE_COMPLEX_DOMINATES` | 최근 거래의 절반 이상이 한 단지에서 나왔어요 | 같은 곳 |
| `HIGH_INDEX_ERROR` | 지수 추정오차가 커서 작은 변화는 읽지 않는 게 좋아요 | 같은 곳 |

flag가 둘 이상이면 위 순서대로 줄을 나눠 전부 보여 준다. 합치지 않는다. flag가 없으면 문장을 내지 않는다. "주의 없음"이라고 쓰지 않는다. 없음을 좋음으로 읽는다.

목록 배지(짧은 형태):

| 코드 | 배지 |
|---|---|
| `FEW_SALES` | 매매 적음 |
| `ONE_COMPLEX_DOMINATES` | 한 단지 쏠림 |
| `HIGH_INDEX_ERROR` | 오차 큼 |

### 3.2 추정오차 구간 (`index_se_band`)

| 코드 | 문장 |
|---|---|
| `LOW` | 지수 추정오차 낮음 |
| `MID` | 지수 추정오차 보통 |
| `HIGH` | 지수 추정오차 높음 |

"낮음"이 좋다는 뜻은 아니지만 사용자는 그렇게 읽는다. 그래서 옆에 항상 매매 건수를 같이 둔다. 오차가 낮은 이유가 거래가 많아서라는 것이 보이게.

### 3.3 12개월 변화 (`change`)

상세 화면의 제목은 `아파트 가격 지수는 얼마나 달라졌을까요?`로 쓰고, 바로 아래에
`{시작 분기} → {끝 분기}`를 표시한다. 예: `2025년 2분기 → 2026년 2분기`.
두 값은 `선택한 동`, `서울 전체`로 나눠 보여 주며 각각 `가격 지수의 1년 변화`라고 적는다.

선택한 동의 값 아래에는 방향을 풀어 쓴 문장을 붙인다.

| 값 | 문장 |
|---|---|
| 양수 | 이 동의 전반적인 가격 수준이 1년 전보다 {절댓값}% 높게 관측됐다는 뜻이에요. |
| 음수 | 이 동의 전반적인 가격 수준이 1년 전보다 {절댓값}% 낮게 관측됐다는 뜻이에요. |
| 0 | 이 동의 전반적인 가격 수준이 1년 전과 같게 관측됐다는 뜻이에요. |
| 결측 | 이 기간의 가격 지수 변화를 계산할 수 없어요. |

이어서 `특정 아파트 가격이 똑같이 변했다는 뜻은 아니에요.`라고 명시한다. 기간 변화는
이미 지나간 기간의 관측값이며 이후 가격 방향을 뜻하지 않는다는 문장도 항상 표시한다.

| 상황 | 문장 |
|---|---|
| 항상 | 선택한 동 {dong_12m_pct}% · 서울 전체 {seoul_12m_pct}% |
| `delta_state == DISTINGUISHABLE` | 서울 평균과 차이 {delta_12m_pct}% (오차 ±{delta_se_pct}%) |
| `delta_state == INDISTINGUISHABLE` | 서울 평균과 구분되지 않아요 (오차 ±{delta_se_pct}%) |

`INDISTINGUISHABLE`일 때 `delta_12m_pct`는 payload에 없다. 프론트가 계산해 넣지 않는다.

각주(고정): "변화율은 동 가격 지수 기준이에요. 서울 평균 자체의 오차는 표시하지 않아요."

### 3.3.1 상단 읽는 법과 설명 상자

동을 선택하면 동 이름 바로 아래에 `이 화면은 이렇게 해석하세요`를 표시한다. 읽는 순서는
`표본 상태 → 1년 전과 비교 → 사실정보`다. 변화율보다 표본 상태를 먼저 확인하고, 가격 지수는
개별 아파트 실거래가와 다르며, 사실정보 한 가지만으로 변화의 원인을 단정하지 않는다고 설명한다.

초보자가 뜻을 오해하기 쉬운 용어에는 물음표 아이콘과 점선 밑줄을 붙인다. 마우스를 올리거나
키보드 초점을 옮기면 짧은 설명 상자가 나타나야 한다. 터치 화면에서는 한 번 눌러 같은 설명을
볼 수 있어야 한다. 적용 대상은 가격 지수, 서울 비교, 최근 5년 범위, 표본 상태의 네 지표,
전세 비중, 입주 세대, 토지거래허가, 정비사업 구역, 중위 가격이다.

### 3.4 5년 최고 대비 (`peak_5y_*`)

| 상황 | 문장 |
|---|---|
| `AT_PEAK` | 최근 5년 중 지금이 지수 최고예요 |
| `DISTINGUISHABLE` | 5년 최고 대비 {peak_5y_gap_pct}% (오차 ±{peak_5y_gap_se_pct}%) |
| `INDISTINGUISHABLE` | 5년 최고와 구분되지 않아요 (오차 ±{peak_5y_gap_se_pct}%) |
| `null` (저거래 동) | 문장 없음. 블록에서 줄을 뺀다 |

각주(고정): "동 가격 지수 기준이에요. 단지별 신고가와 달라요."

금지: "전고점", "회복", "고점", "아직 못 미침". `AT_PEAK`를 "신고가"로 바꾸지 않는다.

### 3.5 μ 참고치 (`reference`)

접힘 제목: "서울 전체 참고치"
본문: "지난 12개월 서울 아파트 지수 변화 {seoul_12m_pct}%. 지나간 기간의 평균이에요."

"기준선", "예측", "전망"이라고 쓰지 않는다.

### 3.6 클러스터 성질 (`structure`)

제목: "클러스터 성질"
본문: `structure_desc` 그대로. 아래 각주 고정.
각주: "가격·전세가율·세대수·신축·위치가 비슷한 동끼리 묶은 결과예요. {cluster_as_of} 기준이고 시장 상황에 따라 바뀔 수 있어요."

상세 필터 제목은 `클러스터`로 쓰고 별도 설명 상자를 붙이지 않는다. 버튼에는 자동 설명을 짧게
줄여 직접 표시한다.

| 자동 설명 | 필터 버튼 이름 |
|---|---|
| 평당가 높음 · 강남 7km대 | 가격대 높음 · 강남 가까움 |
| 강남 13km대 · 도심 9km대 | 강남·도심에서 먼 편 |
| 신축 비중 높음 · 아파트 세대수 적음 | 신축 많음 · 아파트 세대 적음 |
| 아파트 세대수 적음 · 도심 3km대 | 아파트 세대 적음 · 도심 가까움 |

새 자동 설명이 추가되면 `평당가`는 `가격대`, `신축 비중 높음`은 `신축 많음`,
`아파트 세대수`는 `아파트 세대`로 줄인다.

"~권", "~형", "~급"으로 끝나는 이름을 만들지 않는다. 번호(0~3)는 화면에 내지 않는다. 각주에 "국면"을 쓰지 않는다. 금지어다.

### 3.7 함께 볼 동 (`peers`)

제목: "함께 볼 동"
`null`이면 블록을 그리지 않는다. "비교할 동이 없어요"도 쓰지 않는다.
각 항목: `{gu_name} {umd_name}` + `reason`.

금지: "비슷한 동 추천", "대안", "이런 동은 어때요".

### 3.8 거래 흐름 (`flows`)

제목: "분기별 거래 건수"
열 이름: 분기 / 매매 / 전세 / 월세 비중
각주(고정): "분기별 신고 건수예요. 신고가 늦어지면 최근 분기가 낮게 보일 수 있어요."

거래가 없는 분기도 0으로 채워 8칸을 모두 보여 준다. 칸을 빼면 거래가 끊긴 기간이 보이지 않는다.
늘고 줄어든 것을 두고 "늘어나는 중", "줄어드는 중"이라고 쓰지 않는다. 지나간 건수만 보여 준다.

## 4. `structure_desc` 사전 (산출 스크립트용)

`feature-spec.md` §3.3의 z 값으로 변수 2개를 고른 뒤 이 표로 문구를 만든다. z > 0이면 "높음/멀음", z < 0이면 "낮음/가까움". 거리 변수는 부호 대신 클러스터 중앙값을 km 정수로 넣는다.

| 변수 | z > 0 | z < 0 |
|---|---|---|
| `log_ppm2` | 평당가 높음 | 평당가 낮음 |
| `jeonse_ratio` | 전세가율 높음 | 전세가율 낮음 |
| `log_stock` | 아파트 세대수 많음 | 아파트 세대수 적음 |
| `new_share` | 신축 비중 높음 | 신축 비중 낮음 |
| `dist_cbd` | 도심 {km}km대 | 도심 {km}km대 |
| `dist_gangnam` | 강남 {km}km대 | 강남 {km}km대 |

두 문구를 " · "로 잇는다. 예: "평당가 높음 · 강남 6km대". `lat`, `lng`는 후보에서 뺀다.

"평당가 낮음"은 관측이다. "저가"로 바꾸지 않는다.

## 5. `peers[].reason` 사전 (산출 스크립트용)

거리 기여가 가장 작은 변수 2개를 명사로 바꾸고 "{A}와 {B}가 가까워요"로 만든다. 조사는 받침에 따라 "와/과".

| 변수 | 명사 |
|---|---|
| `log_ppm2` | 평당가 |
| `jeonse_ratio` | 전세가율 |
| `log_stock` | 세대수 |
| `new_share` | 신축 비중 |
| `lat`, `lng` | 위치 |
| `dist_cbd` | 도심 거리 |
| `dist_gangnam` | 강남 거리 |

`lat`과 `lng`가 둘 다 뽑히면 "위치가 가까워요" 하나로 합치고 세 번째 변수를 더한다.
