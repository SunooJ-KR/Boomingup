# 제품 기획 기준

> 2026-09-17 개정. 예측 중심 초안을 판단 보조 제품 기준으로 교체했다. 상세 화면 구성과 성공 기준은 `docs/investment-support-plan.md`, 데이터 계약은 `docs/payload-schema.md`를 따른다.

## 1. 대상 사용자와 제공 가치

| 항목 | 내용 |
|---|---|
| 1차 대상 | 서울 아파트 매매를 검토하며 여러 법정동을 비교하는 개인 사용자 |
| 핵심 질문 | 이 동의 관측값을 얼마나 조심해서 읽어야 하는가, 서울 전체와 구분되는 변화가 있었는가, 어떤 구조의 동인가, 함께 비교할 동은 어디인가 |
| 제공 형태 | 표본 상태, 오차를 동반한 지난 12개월 변화, 클러스터 성질, 함께 볼 동, 거래·전세·공급·정비사업 사실 정보 |
| 제공하지 않는 것 | 미래 수익률, 매수·매도·보유 권고, 동 순위, 적정가, 특정 단지 판단, 투자 성향 진단 |

제품의 역할은 정답을 알려 주는 것이 아니라, 사용자가 지역을 비교할 때 관측값과 한계를 같은 기준으로 읽도록 돕는 것이다. 새 외부 데이터에 의존하기보다 현재 DB와 검증된 산출물을 우선 사용한다.

## 2. 제품 원칙

| 원칙 | 적용 방식 |
|---|---|
| 관측과 해석 분리 | 거래량·가격·전세가율 같은 사실을 원인이나 전망으로 바꾸지 않는다 |
| 불확실성 우선 | 거래가 적거나 한 단지에 쏠리거나 지수 오차가 크면 결과보다 주의 문구를 먼저 보여 준다 |
| 순위 방지 | 목록에 변화율을 싣지 않고 변화율 정렬과 변화율 지도 색칠을 제공하지 않는다 |
| 설명 가능성 | 클러스터 성질과 함께 볼 동에는 사용한 변수와 자동 생성 근거를 함께 표시한다 |
| 구현 가능성 | 지도 경계 데이터가 없어도 검색·목록·상세 흐름이 동작하도록 한다 |

## 3. 사용자 흐름

헤더의 `Boomingup`을 누르면 검색어, 자치구, 상세 조건, 선택한 동과 페이지를 모두 초기화하고
첫 화면으로 돌아간다.
화면을 아래로 내리면 우하단에 맨 위로 이동하는 버튼을 표시한다.

1. 첫 화면에서 전체 법정동 목록과 서울 자치구 지도를 함께 본다.
2. 지도에서 자치구를 선택하면 해당 지역으로 확대되고 그 안의 법정동만 표시된다. 목록에서 법정동을 선택할 때는 자치구와 검색·필터 조건을 바꾸지 않고 해당 동의 상세를 열며, 지도는 법정동 보기로 전환해 선택한 동 중심으로 확대한다.
3. 법정동 검색과 가격대·표본 상태·클러스터 성질로 목록을 좁히고, ㎡당 중앙가나 지역 특성의 높은순·낮은순으로 정렬한다.
4. 목록에서 동을 선택한다. 목록에는 법정동·자치구, ㎡당 중앙가, 표본 주의 여부만 보이고 클러스터는 법정동 이름 색으로 구분한다.
5. 처음 조회하는 동은 머신러닝 분석 산출물을 준비하는 단계를 확인한 뒤, 상세에서 표본 상태와 지난 12개월 변화·오차를 본다. 이미 조회한 동은 기다리지 않고 바로 표시한다.
6. 거래 흐름, 전세·공급·정비사업 같은 사실 정보를 확인한다.
7. 구조가 비슷한 동과 서울 전체 참고치를 필요할 때 펼쳐 본다.

## 4. 화면 정보 구조

| 순서 | 블록 | 역할 |
|---|---|---|
| 1 | 표본 상태 | 매매 부족, 한 단지 쏠림, 지수 오차를 독립 flag로 표시 |
| 2 | 지난 12개월 변화 | 동 변화와 서울 평균을 표시하고, 차이가 오차보다 작으면 수치를 숨김 |
| 3 | 거래 흐름 | 최근 8분기 매매·전세 건수와 월세 비중 |
| 4 | 사실 정보 | 전세가율, 정비사업, 준공, 규제, 면적대별 매매 가격 분포, 최근 거래 |
| 5 | 클러스터 성질·함께 볼 동 | K-S 클러스터의 자동 설명과 같은 묶음 안 최근접 동 |
| 6 | 서울 전체 참고치 | 예측이 아닌 지난 기간 평균임을 밝힌 접힘 영역 |

처음 조회하는 법정동의 상세는 API 요청과 동시에 준비하며, 빠르게 응답해도 약 1초 동안 분석
전환 화면을 보여 준다. 통계 모델과 머신러닝은 화면에서 `데이터 모델링`으로 함께 표시한다.
실시간 학습이나 미래 가격 계산으로 표현하지 않고 거래·표본 확인, 가격 지수·오차 확인,
군집 결과·유사 동 연결 순서로 안내한다. 오류는 최소 시간과 관계없이 바로 표시하고, 캐시에 있는
상세는 전환 시간을 다시 적용하지 않는다.

첫 화면의 지도 자치구 표시는 같은 색을 쓰며 우열을 나타내지 않는다. 자치구 선택 뒤 지도는 표본 상태와
클러스터만 색으로 구분한다. 변화율에는 색을 쓰지 않는다. 상세 규칙은
`docs/investment-support-plan.md` §4를 따른다.

## 5. MVP 범위

- 표본 주의 flag 세 가지
- 오차를 동반한 12개월 변화와 5년 최고 지수 대비 위치
- 클러스터 성질과 함께 볼 동
- payload v2와 화면 컴포넌트 교체
- 문구 자동 검사

이벤트 전후 경로, leave-one-complex-out 변화율, 면적대 구성 변화는 사용자 검증 뒤의 2차 후보로 둔다. 진행 순서와 게이트는 `docs/process.md`를 따른다.

## 6. 문구와 검증

화면 문장은 `docs/wording-guide.md`를 따른다. 문구는 쉬운 `~해요`체로 쓰고 관측, 원인, 전망, 우열을 구분한다. 데이터 계약과 null 처리 규칙은 `docs/payload-schema.md`, 산식과 경계 사례는 `docs/feature-spec.md`가 정본이다.

## 7. AI 활용 분석

이 프로젝트에서 AI는 미래 가격이 오를 동을 맞히는 도구가 아니라, 서울 법정동 데이터를 비교 가능한 형태로 정리하는 보조 도구로 사용한다. 초기에는 동별 12개월 가격 변화를 예측하는 모델도 검토했지만, 검증 결과가 기준선을 넘지 못해 제품 기능으로 채택하지 않았다. 따라서 현재 제품은 AI가 투자 판단을 대신하거나 매수·매도 결론을 제시하지 않도록 범위를 제한한다.

AI를 주요하게 활용한 부분은 두 가지다. 첫째, 서울 346개 법정동을 구조가 비슷한 그룹으로 묶는 군집화다. 가격 수준, 전세가율, 아파트 재고 규모, 신축 비중, 위도·경도, 도심 거리, 강남 거리 등 8개 변수를 표준화한 뒤 k-means로 4개 그룹을 만든다. 이 그룹은 좋은 지역과 나쁜 지역을 나누는 등급이 아니라, 사용자가 비슷한 조건의 동을 같은 기준으로 비교할 수 있게 만드는 비교 단위다. 그룹 이름도 사람이 가치 판단으로 붙이지 않고, 서울 전체와 가장 다르게 나타나는 변수 두 개를 골라 자동 설명한다.

둘째, 사용자가 선택한 동과 함께 볼 만한 동을 찾는 유사도 탐색이다. 선택한 동이 속한 그룹 안에서 같은 8개 변수의 거리를 계산하고, 가장 가까운 동 5개를 찾아 상세 화면에 보여 준다. 이 기능은 추천 엔진이 아니다. 특정 동을 사라고 권하는 대신, 구조적으로 비슷해 나란히 비교해 볼 수 있는 후보를 제시한다. 그래서 화면 문구에서도 `추천`이라는 표현을 쓰지 않고 `함께 볼 동`으로 안내한다.

AI와 함께 통계 모델도 사용한다. 헤도닉 가격 지수는 단지, 면적, 층처럼 거래 물건의 차이를 먼저 보정하고 동별 가격 흐름을 계산한다. 거래가 적은 동은 값이 크게 흔들릴 수 있으므로 ridge 수축을 적용하고, 지수마다 추정오차를 함께 계산한다. 이 값은 머신러닝이 학습한 예측값이 아니라 과거 거래를 비교 가능하게 만든 추정값이다.

사용자가 AI 산출물을 과신하지 않도록 규칙 기반 표시도 함께 둔다. 최근 1년 매매가 20건 미만이면 `FEW_SALES`, 한 단지 거래가 절반을 넘으면 `ONE_COMPLEX_DOMINATES`, 지수 추정오차가 크면 `HIGH_INDEX_ERROR`를 표시한다. 동과 서울 평균의 차이가 오차보다 충분히 크지 않으면 수치를 강조하지 않고 `서울 평균과 구분되지 않음`으로 보여 준다. 즉 제품은 AI 결과보다 불확실성을 먼저 보여 주도록 설계되어 있다.

사용하지 않기로 한 AI도 명확히 기록했다. Ridge, LightGBM, 자치구 모멘텀, 구조 클러스터 모멘텀, 가격 경로 클러스터 등 여러 예측 후보를 rolling-origin 방식으로 검증했지만, 12개월 동별 상대 변화 예측에서 기준선을 안정적으로 이기지 못했다. 일부 약한 신호는 측정오차에서 생긴 것으로 확인했다. 이 결과 때문에 제품은 미래 수익률, 동 순위, 매수·매도 판단, 특정 단지 판단을 제공하지 않는다.

정리하면, 이 프로젝트의 AI 활용 방식은 `예측`보다 `비교 구조화`에 가깝다. 통계 모델은 가격 흐름과 오차를 계산하고, 규칙은 그 숫자를 얼마나 조심해서 읽어야 하는지 알려 주며, 머신러닝은 어떤 동끼리 비교하면 좋은지 정리한다. 사용자는 이 결과를 투자 결론이 아니라 지역을 더 신중하게 비교하기 위한 참고 정보로 사용한다.
