# 제품 기획 기준

> 2026-09-17 개정. 예측 중심 초안을 판단 보조 제품 기준으로 교체했다. 상세 화면 구성과 성공 기준은 `docs/investment-support-plan.md`, 데이터 계약은 `docs/payload-schema.md`를 따른다.

## 1. 대상 사용자와 제공 가치

| 항목 | 내용 |
|---|---|
| 1차 대상 | 서울 아파트 매매를 검토하며 여러 법정동을 비교하는 개인 사용자 |
| 핵심 질문 | 이 동의 관측값을 얼마나 조심해서 읽어야 하는가, 서울 전체와 구분되는 변화가 있었는가, 어떤 구조의 동인가, 함께 비교할 동은 어디인가 |
| 제공 형태 | 표본 상태, 오차를 동반한 지난 12개월 변화, 클러스터 성질, 함께 볼 동, 거래·전세·공급·정비사업 사실 정보 |
| 제공하지 않는 것 | 미래 수익률, 매수·매도·보유 권고, 동 순위, 적정가, 특정 단지 판단, 투자 성향 진단 |

제품의 역할은 정답을 알려 주는 것이 아니라, 사용자가 지역을 비교할 때 관측값과 한계를 같은 기준으로 읽도록 돕는 것이다. 새 외부 데이터에 의존하기보다 현재 DB와 검증된 산출물을 우선 사용한다.

## 2. 제품 원칙

| 원칙 | 적용 방식 |
|---|---|
| 관측과 해석 분리 | 거래량·가격·전세가율 같은 사실을 원인이나 전망으로 바꾸지 않는다 |
| 불확실성 우선 | 거래가 적거나 한 단지에 쏠리거나 지수 오차가 크면 결과보다 주의 문구를 먼저 보여 준다 |
| 순위 방지 | 목록에 변화율을 싣지 않고 변화율 정렬과 변화율 지도 색칠을 제공하지 않는다 |
| 설명 가능성 | 클러스터 성질과 함께 볼 동에는 사용한 변수와 자동 생성 근거를 함께 표시한다 |
| 구현 가능성 | 지도 경계 데이터가 없어도 검색·목록·상세 흐름이 동작하도록 한다 |

## 3. 사용자 흐름

헤더의 `Boomingup`을 누르면 검색어, 자치구, 상세 조건, 선택한 동과 페이지를 모두 초기화하고
첫 화면으로 돌아간다.
화면을 아래로 내리면 우하단에 맨 위로 이동하는 버튼을 표시한다.

1. 첫 화면에서 전체 법정동 목록과 서울 자치구 지도를 함께 본다.
2. 지도에서 자치구를 선택하면 해당 지역으로 확대되고 그 안의 법정동만 표시된다. 상세 조건이 없을 때 목록에서 법정동을 바로 선택해도 해당 자치구로 전환된다. 상세 조건이 적용된 목록에서는 자치구를 자동 입력하지 않고 조건을 유지한 채 상세만 연다.
3. 법정동 검색과 가격대·표본 상태·클러스터 성질·지역 태그로 목록을 더 좁힌다.
4. 목록에서 동을 선택한다. 목록에는 거래 수, ㎡당 중앙가, 표본 flag, 구조 설명만 보인다.
5. 상세에서 표본 상태를 먼저 확인한 뒤 지난 12개월 변화와 오차를 본다.
6. 거래 흐름, 전세·공급·정비사업 같은 사실 정보를 확인한다.
7. 구조가 비슷한 동과 서울 전체 참고치를 필요할 때 펼쳐 본다.

## 4. 화면 정보 구조

| 순서 | 블록 | 역할 |
|---|---|---|
| 1 | 표본 상태 | 매매 부족, 한 단지 쏠림, 지수 오차를 독립 flag로 표시 |
| 2 | 지난 12개월 변화 | 동 변화와 서울 평균을 표시하고, 차이가 오차보다 작으면 수치를 숨김 |
| 3 | 거래 흐름 | 최근 8분기 매매·전세 건수와 월세 비중 |
| 4 | 사실 정보 | 전세가율, 정비사업, 준공, 규제, 면적대별 매매 가격 분포, 최근 거래 |
| 5 | 클러스터 성질·함께 볼 동 | K-S 클러스터의 자동 설명과 같은 묶음 안 최근접 동 |
| 6 | 서울 전체 참고치 | 예측이 아닌 지난 기간 평균임을 밝힌 접힘 영역 |

첫 화면의 지도 자치구 표시는 같은 색을 쓰며 우열을 나타내지 않는다. 자치구 선택 뒤 지도는 표본 상태와
클러스터만 색으로 구분한다. 변화율에는 색을 쓰지 않는다. 상세 규칙은
`docs/investment-support-plan.md` §4를 따른다.

## 5. MVP 범위

- 표본 주의 flag 세 가지
- 오차를 동반한 12개월 변화와 5년 최고 지수 대비 위치
- 클러스터 성질과 함께 볼 동
- payload v2와 화면 컴포넌트 교체
- 문구 자동 검사

이벤트 전후 경로, leave-one-complex-out 변화율, 면적대 구성 변화는 사용자 검증 뒤의 2차 후보로 둔다. 진행 순서와 게이트는 `docs/process.md`를 따른다.

## 6. 문구와 검증

화면 문장은 `docs/wording-guide.md`를 따른다. 문구는 쉬운 `~해요`체로 쓰고 관측, 원인, 전망, 우열을 구분한다. 데이터 계약과 null 처리 규칙은 `docs/payload-schema.md`, 산식과 경계 사례는 `docs/feature-spec.md`가 정본이다.
